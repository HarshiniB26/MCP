Answer in JSON with these fields:
- rule_decision: the decision word for each item from the rule results (Approved, Denied, or Escalated).
- draft_decision: the decision word for each item as the draft states it.
- same_decision: true if the two are the same word for every item, and an escalated item does not say approved or denied.
- must_appear_present: true if the draft contains every entry under "Must appear in the draft", written exactly.
- nothing_invented: true if every name, date, count, maximum, wait, and case id in the draft appears in the facts or in an Observation with the same value.
- no_extra_promise: true if the draft does not promise more than the tools allow. A replacement means the oldest item is returned, so the employee does not keep both.
- sound_reasoning: true if the trace looked up this employee, their role's limits, and every requested item, and the rule results follow from those Observations.
- reason: one sentence on why the draft passes or fails.
- final_answer: if all five checks are true, the draft rewritten as the final reply to the employee, in two to four clear sentences. Otherwise an empty string.

When you write final_answer:
- Start with the decision word: Approved, Denied, or Escalated.
- Name the employee and the item.
- Give the reason for the decision from the tool results, for example the count and maximum, or the date the wait ends.
- Say what happens next: for a replacement, the oldest item is returned; for an escalation, a person reviews the case id.
- Keep every fact the same as the draft. Do not add a fact, a promise, or a date that is not in the facts.
